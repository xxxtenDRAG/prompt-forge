# 通用七视角推演清单

本文档是 Phase 2 内部推演与 Phase 5 验收的核心依据，适用于**任何类型**的任务。推演时依次走完七个视角；每个视角回答完所有问题后，把结论汇总进方案蓝图。所有开放问题必须当场拍板并记录理由，禁止留白或抛回给用户。若任务命中领域 playbook，则在对应视角下叠加该 playbook 的专属深化清单（如游戏在视角三/四叠加玩法、关卡、数值、视听九视角）。

---

## 视角一：目标定义师（做什么、不做什么）

- [ ] 用一句话写出真实目标：用户拿到什么、用来干什么、什么算成功。
- [ ] 明确"完成"的可验证标准（能玩、能上线、能交付阅读、能跑出结论）。
- [ ] 划定范围边界：明确列出 3 件"本项目不做"的事，防止范围蔓延。
- [ ] 识别用户的显性需求与隐性期望（如"发朋友圈好看""领导能看懂""面试能演示"）。

## 视角二：受众分析师（给谁用）

- [ ] 定义目标使用者/读者：是谁、什么场景接触、投入多长时间。
- [ ] 定义受众的知识水平：零门槛还是有专业背景，决定用语深度。
- [ ] 明确受众的核心诉求排序（最多 3 个），按优先级分配打磨资源。
- [ ] 换位演练：首次接触的前 30 秒，受众看到什么、理解什么、下一步做什么。

## 视角三：方案架构师（结构与流程）

- [ ] 把目标拆解为 3–7 个核心模块/章节/功能块，每个有明确的输入与产出。
- [ ] 画出整体流程/结构：从开始到完成的最短路径，无死胡同。
- [ ] 定义核心循环或主线逻辑：使用者重复做的动作 / 读者跟随的主线。
- [ ] 每个模块给出"至少做到什么程度"的下限定义，作为验收依据。

## 视角四：打磨与亮点设计师（凭什么好）

- [ ] 设计至少 3 个打磨点/亮点机制，每个说明：是什么、何时出现、对体验的作用。
- [ ] 每次关键操作/关键节点都有即时反馈（视觉、听觉、文字、数据反馈至少其一）。
- [ ] 设计至少 1 个惊喜时刻（彩蛋、罕见效果、超出预期的细节）值得用户记住。
- [ ] 检查一致性：风格、语气、命名、视觉全局统一，无拼接感。

## 视角五：约束与风险官（现实的墙）

- [ ] 明确技术/资源约束：零后端 or 有后端、离线可用性、运行环境、篇幅上限。
- [ ] 依赖外部资源时确认兜底（无图库时程序化生成、无数据时模拟数据并标注）。
- [ ] 列出 3 个最可能翻车的点，并为每个准备规避方案写进蓝图。
- [ ] 检查合规与安全红线：版权素材、敏感内容、隐私数据不越界。

## 视角六：降级与容错师（失败的状态）

- [ ] 定义所有异常/失败状态的处理：出错时用户看到什么、如何恢复、如何重来。
- [ ] 覆盖边界情况：空数据、超大量数据、断网、中断重来、非法输入。
- [ ] 提供"从头再来"的最短路径：重置/重开入口不超过 1 次点击。
- [ ] "差一点"体验：失败/不足时给出明确的差距信息与改进建议，而非笼统报错。

## 视角七：QA 验收官（完成的标准）

根据任务类型生成验收清单并执行。通用底线项（任何任务都必须过）：

- [ ] 核心目标闭环完整：能开始、能走完全程、能正常结束/重来。
- [ ] 3 个亮点机制真实生效，不是纸面设计。
- [ ] 异常与失败状态有处理，不会白屏/报错/中断无提示。
- [ ] 首次接触的前 30 秒无需说明书即可理解下一步。
- [ ] 实际运行/阅读验证过，不是"理论上能行"。
- [ ] 与蓝图设计一致：无擅自变更、无遗漏模块。

领域专属验收项叠加自对应 playbook。验收发现问题当场修复，修复后重跑整张清单。

## 视角快查表

| 视角 | 一句话职责 | 主要产出 |
|------|-----------|----------|
| 目标定义 | 定成功标准与范围 | 一句话目标 + 不做清单 |
| 受众分析 | 定给谁、按什么优先 | 受众画像 + 诉求排序 |
| 方案架构 | 定结构与流程 | 模块拆解 + 流程图 |
| 打磨设计 | 定亮点与反馈 | 3 亮点 + 反馈定义 |
| 约束风险 | 定现实边界 | 约束表 + 翻车点规避 |
| 降级容错 | 定失败出路 | 异常处理表 |
| QA 验收 | 定完成标准 | 验收清单 |
