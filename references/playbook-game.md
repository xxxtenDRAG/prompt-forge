# 游戏 Playbook — 九视角深化清单

游戏类任务在 Phase 2 走完通用七视角（`universal-lenses.md`）后，叠加本清单做领域深化；本清单视角九同时提供游戏专属验收项，供 Phase 5 使用。所有开放问题必须当场拍板并记录理由，禁止留白或抛回给用户。游戏默认单机约束：零后端、本地存档、离线可玩、纯前端实现。

---

## 视角一：玩法设计师（核心循环）

- [ ] 用一句话写出核心循环：玩家做什么操作 → 得到什么反馈 → 产生什么新目标。
- [ ] 明确胜负/回合判定规则，无歧义（例如消消乐的"三连即消除、斜向不算"）。
- [ ] 定义至少 1 个"深度机制"：让熟练玩家有提升空间的规则（连锁、连击、技能组合、资源权衡等）。
- [ ] 定义至少 1 个"意外机制"：打破单调的变化源（特殊方块、随机事件、道具掉落等）。
- [ ] 确认操作输入与判定响应一一对应，不存在"不知道为什么失败"的情况。

## 视角二：关卡设计师（阶段与教学）

- [ ] 前 30 秒内让玩家完成第一次成功操作（教学即玩，不用说明书）。
- [ ] 设计渐进结构：至少 3 个阶段（入门期 / 成长期 / 挑战期），每阶段引入 1 个新元素。
- [ ] 每个阶段有明确的"毕业标志"（通过分数、存活时间或关卡数）。
- [ ] 保证任何时刻玩家知道"我现在该干什么"。

## 视角三：数值策划（难度与随机性）

- [ ] 给出难度曲线公式或分阶段数值表（起点宽容、爬坡有感知、后期陡峭）。
- [ ] 首局失败率控制在 20% 以内；"差一点就成功"是主要的失败体验。
- [ ] 明确随机性策略：哪里随机（增加变化）、哪里保底（防止挫败，如必给可用棋步）。
- [ ] 所有数值有上限与下限，不可能出现死局或数值溢出。

## 视角四：用户体验设计师（手感）

- [ ] 每次操作在 100ms 内给出视觉/听觉反馈。
- [ ] 关键事件有强调反馈：得分飘字、屏幕震动、连击提示、粒子效果至少覆盖"成功"与"失败"两类事件。
- [ ] 惜败体验设计：失败画面必须给出"差一点"的信息（差 1 步、差 1 个方块）与"再试一次"的一键入口。
- [ ] 暂停、重开、静音、进度重置等基础功能可用。

## 视角五：视听设计师（表现）

- [ ] 定一个美术风格关键词（扁平卡通 / 像素 / 手绘 / 几何极简）并保持全局一致。
- [ ] 主色、强调色、危险色三色体系明确，按钮与背景对比度足够。
- [ ] 音效清单：操作音、成功音、失败音、BGM（可用 WebAudio 程序化生成，不依赖外部素材）。
- [ ] 动画原则：消除/得分/受击三类事件必须有动画，时长 150–400ms。

## 视角六：留存设计师（动机）

- [ ] 单局时长定义合理（休闲单机建议 1–5 分钟一局）。
- [ ] 至少 1 个跨局目标：最高分、成就、解锁内容其一。
- [ ] "再来一局"摩擦最小：结算界面的一键重开不需要任何额外点击路径。
- [ ] 至少 1 个惊喜时刻（彩蛋、罕见事件、爆分瞬间）值得玩家记住。

## 视角七：技术架构师（单机实现）

- [ ] 技术选型：默认 HTML5 + Canvas（或 DOM），零构建依赖、双击即玩。
- [ ] 核心数据结构定义（棋盘矩阵 / 实体列表 / 状态机），逻辑与渲染分离。
- [ ] 进度持久化：localStorage 存最高分与设置，提供导出/清空。
- [ ] 状态机完备：开始 → 游玩 → 暂停 → 结算 → 重开，无死状态。
- [ ] 帧率目标 60fps；单文件不超过必要复杂度，禁止引入框架除非用户要求。

## 视角八：可访问性顾问（低门槛）

- [ ] 支持鼠标和触摸（移动端可玩），必要时补键盘操作。
- [ ] 文案无术语门槛；颜色不作为唯一信息载体（色弱可玩）。
- [ ] 提供静音开关与基础设置。
- [ ] 容错：误操作可撤销或代价极小（视玩法适配）。

## 视角九：QA 验收官（验收清单）

开发完成后逐项自检，全部通过才允许交付：

- [ ] 核心玩法闭环完整：能开始、能玩、能赢或能输、能重开。
- [ ] 成长/变化机制 ≥ 3 个真实生效（不是纸面设计）。
- [ ] 教学引导存在且首次可自然跟随。
- [ ] 音画反馈存在（成功/失败/操作三类事件均有）。
- [ ] 进度保存真实生效：刷新/关闭后最高分与设置不丢。
- [ ] 无控制台报错，无未捕获异常。
- [ ] 在浏览器中实际运行验证过，不是"理论上能跑"。
- [ ] 失败有"差一点"提示与一键重开。
- [ ] 单局时长与难度曲线符合蓝图设计。

验收发现问题当场修复，修复后重跑整张清单。
