# 文档 Playbook — 文档与报告速查基线

文档/报告/文章/方案/文案类任务在通用七视角基础上叠加本基线。默认约束：一次读完不用来回翻、每个论点有支撑、结构与结论对得上目标。

---

## 结构与主线

- 先定一句话主线（读者读完能带走的那句话），全文围绕它展开。
- 结构模板定死：概述（结论先行）→ 展开（3–5 个分论点，每个独立成节）→ 收尾（结论 + 建议动作）。
- 每个分论点内部遵循"观点 → 依据 → 小结"三段式。
- 每节标题即信息（"Q3 华东区增长 40%，主因新客补贴"优于"增长情况"）。

## 内容质量

- 关键数字给来源与口径；预测与事实分开标注，不混写。
- 图表优先：趋势用折线、构成用饼/条形、对比用表格；一图一结论作标题。
- 篇幅纪律：按用途定上限（汇报 ≤3 页、方案 ≤10 页），超出部分入附录。
- 删掉一切"正确的废话"（众所周知的背景铺垫）。

## 语气与受众适配

- 按受众定术语深度：决策层用结论语言，执行层用操作语言。
- 全文语气统一（正式/务实/轻快，三选一并贯彻）。
- 建议可执行：每条建议有"谁、做什么、预期效果"。

## 常见坑

- 结论与数据脱节（结论说了数据不支持的话）。
- 结构对称强迫症：为了工整硬凑平级章节。
- 附录塞满正文删掉的内容，读者根本不会看。

## 专属验收项（叠加进验收清单）

- [ ] 结论先行：第一屏/第一页就能看到核心结论。
- [ ] 每个论点都有支撑（数据、事实或明确标注的假设）。
- [ ] 标题信息完整，仅读目录+标题能还原全文骨架。
- [ ] 篇幅在既定上限内，无"正确的废话"。
- [ ] 数字口径一致（同一指标全文只有一个数）。
